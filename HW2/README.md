## Выполнение задания

### 1. Выбор открытого набора данных

Использовал датасет all_stocks_5yr.csv с данными о ценах акций за 5 лет. Взял его с Kaggle, как в примере из задания. Файл находится в data/all_stocks_5yr.csv. Формат CSV с колонками: date, open, high, low, close, volume, Name.

### 2. Создание базы данных и загрузка таблиц

Создал базу данных stocks_hw в Hive. В ней две таблицы:

- stg_prices_csv — внешняя таблица для чтения CSV файла из HDFS
- stocks_raw — основная таблица с данными в формате Parquet

SQL скрипт для создания БД и загрузки данных находится в data/load_data.sql.

### 3. Построение аналитических витрин

Создал 6 витрин, использовал все требуемые конструкции:

1. avg_close_per_company — средняя цена закрытия по компаниям

   - Использовал: WHERE, GROUP BY, AVG, COUNT, ORDER BY

2. max_volume_day — день с максимальным объемом торгов по каждой компании

   - Использовал: WINDOW (ROW_NUMBER), PARTITION BY, ORDER BY, WHERE

3. quarterly_growth — квартальная динамика роста цен

   - Использовал: WINDOW (LAG), PARTITION BY, ORDER BY, GROUP BY, WHERE

4. top5_by_volume — топ-5 компаний по среднему объему торгов

   - Использовал: GROUP BY, HAVING, AVG, COUNT, ORDER BY

5. volatility_comparison — сравнение акций с высокой и низкой волатильностью

   - Использовал: UNION ALL, GROUP BY, HAVING, STDDEV, WHERE

6. monthly_summary_with_avg — месячная статистика с JOIN
   - Использовал: GROUP BY, JOIN, WHERE, COUNT, ORDER BY

Все требуемые конструкции использованы: WHERE, COUNT, GROUP BY, HAVING, ORDER BY, JOIN, UNION (UNION ALL), WINDOW (ROW_NUMBER, LAG, PARTITION BY).

### 4. Описания витрин

К каждой витрине добавил описание с 7 тезисами. Описания находятся в файле data/data_marts.sql в виде комментариев перед каждой витриной. Там объясняется, какие конструкции используются и зачем нужна витрина.

## Запуск в Docker контейнере

Все запускается в Docker контейнере, так проще.

### Шаг 1: Запуск Docker контейнера

```bash
docker-compose up -d
```

### Шаг 2: Ожидание запуска сервисов (30-60 секунд)

```bash
docker exec -it hadoop-hw2 bash
# Проверить процессы
jps
# Должны быть: NameNode, DataNode, ResourceManager, NodeManager
```

### Шаг 3: Загрузка данных и создание витрин

В контейнере выполнить:

```bash
bash /data/setup_hive.sh
```

Скрипт сам:

1. Создает директории в HDFS
2. Загружает CSV файл в HDFS
3. Выполняет SQL скрипты для создания таблиц и витрин

### Шаг 4: Проверка результатов

```bash
# Подключение к Hive через Beeline
beeline -u "jdbc:hive2://localhost:10000" -n root -p ""

# В Beeline:
USE stocks_hw;
SHOW TABLES;

# Просмотр данных витрин
SELECT * FROM avg_close_per_company LIMIT 10;
SELECT * FROM max_volume_day LIMIT 10;
SELECT * FROM quarterly_growth LIMIT 10;
SELECT * FROM top5_by_volume;
SELECT * FROM volatility_comparison LIMIT 20;
SELECT * FROM monthly_summary_with_avg LIMIT 10;
```

### Альтернативный способ: Ручная загрузка данных

Если автоматический скрипт не работает, можно сделать вручную:

```bash
# В контейнере
# 1. Загрузка CSV в HDFS
hdfs dfs -mkdir -p /data/stocks_hw/stg_prices_csv
hdfs dfs -put /data/all_stocks_5yr.csv /data/stocks_hw/stg_prices_csv/

# 2. Выполнение SQL скриптов через Beeline
beeline -u "jdbc:hive2://localhost:10000" -n root -p "" -f /data/load_data.sql
beeline -u "jdbc:hive2://localhost:10000" -n root -p "" -f /data/data_marts.sql
```

## Описание аналитических витрин

### 1. avg_close_per_company — Средняя цена закрытия по компаниям

Используемые конструкции: WHERE, GROUP BY, AVG, COUNT, ORDER BY

Описание: Витрина показывает среднюю цену закрытия акций для каждой компании за весь период. Можно сравнить средние цены между компаниями и найти самые дорогие и дешевые акции.

Тезисы:

1. Считается средняя цена закрытия (AVG(close)) для каждой компании
2. WHERE фильтрует записи с NULL значениями
3. GROUP BY name группирует данные по компаниям
4. ORDER BY DESC сортирует по убыванию средней цены
5. Помогает быстро оценить средний уровень цен акций
6. Можно использовать для сравнения стоимости акций
7. Позволяет найти компании с самыми стабильными ценами

---

### 2. max_volume_day — День с максимальным объемом торгов

Используемые конструкции: WINDOW (ROW_NUMBER), PARTITION BY, ORDER BY, WHERE

Описание: Витрина находит день с максимальным объемом торгов для каждой компании. Это помогает найти пики торговой активности и связать их с конкретными датами, что полезно для анализа событий, которые вызвали повышенный интерес к акциям.

Тезисы:

1. Используется оконная функция ROW_NUMBER() для ранжирования записей
2. PARTITION BY name делает независимое ранжирование для каждой компании
3. ORDER BY volume DESC сортирует по убыванию объема торгов
4. WHERE rn = 1 выбирает только записи с максимальным объемом
5. Помогает найти дни с очень высокой торговой активностью
6. Можно использовать для анализа связи между событиями и объемом торгов
7. Позволяет найти компании с самыми волатильными торговыми днями

---

### 3. quarterly_growth — Квартальная динамика роста цен

Используемые конструкции: WINDOW (LAG), PARTITION BY, ORDER BY, GROUP BY, WHERE

Описание: Витрина показывает динамику изменения цены закрытия по кварталам для каждой компании. Используя оконные функции, считается процентное изменение цены относительно предыдущего квартала, что позволяет отслеживать тренды роста или падения.

Тезисы:

1. Используется оконная функция LAG() для получения значения предыдущего периода
2. PARTITION BY name делает расчеты в рамках каждой компании
3. ORDER BY date обеспечивает правильную последовательность временных рядов
4. Считается процентное изменение цены между кварталами
5. Помогает найти сезонные паттерны и тренды роста/падения
6. Можно использовать для прогнозирования будущей динамики цен
7. Позволяет сравнивать квартальную производительность разных компаний

---

### 4. top5_by_volume — Топ-5 компаний по объему торгов

Используемые конструкции: GROUP BY, HAVING, AVG, COUNT, ORDER BY

Описание: Витрина находит пять компаний с наибольшим средним дневным объемом торгов. Используется HAVING для фильтрации результатов после агрегации, что позволяет исключить компании с недостаточным количеством данных или аномальными значениями.

Тезисы:

1. GROUP BY группирует данные по компаниям
2. HAVING фильтрует после агрегации (исключает NULL и малые объемы)
3. COUNT(\*) проверяет достаточность данных по каждой компании
4. ORDER BY avg_volume DESC сортирует компании по убыванию среднего объема
5. LIMIT 5 ограничивает результат пятью компаниями
6. Помогает найти самые ликвидные акции на рынке
7. Можно использовать для анализа инвестиционной привлекательности компаний

---

### 5. volatility_comparison — Сравнение волатильности

Используемые конструкции: UNION ALL, GROUP BY, HAVING, STDDEV, WHERE

Описание: Витрина объединяет данные о компаниях с высокой и низкой волатильностью цен, используя UNION ALL. Волатильность считается как стандартное отклонение цен закрытия. Это позволяет разделить компании на две категории для сравнения.

Тезисы:

1. UNION ALL объединяет два набора данных
2. STDDEV(close) считает стандартное отклонение как меру волатильности
3. HAVING разделяет компании на категории по уровню волатильности
4. Первый SELECT выбирает компании с высокой волатильностью (> порогового значения)
5. Второй SELECT выбирает компании с низкой волатильностью (<= порогового значения)
6. Помогает инвесторам выбрать акции по их риск-профилю
7. Можно использовать для построения диверсифицированного портфеля

---

### 6. monthly_summary_with_avg — Месячная статистика с JOIN

Используемые конструкции: GROUP BY, JOIN, WHERE, COUNT, ORDER BY

Описание: Витрина создает месячную статистику по ценам закрытия и объему торгов, а потом использует JOIN для объединения с данными о средних ценах по компаниям. Это позволяет сравнивать месячные показатели с общими средними значениями.

Тезисы:

1. GROUP BY группирует данные по компании и месяцу
2. SUBSTR(date, 1, 7) извлекает год и месяц из даты для группировки
3. JOIN объединяет месячную статистику с общими средними показателями
4. WHERE фильтрует данные перед агрегацией
5. COUNT(\*) считает количество торговых дней в каждом месяце
6. Помогает найти сезонные паттерны в торговле акциями
7. Позволяет сравнивать месячные показатели с долгосрочными средними значениями
